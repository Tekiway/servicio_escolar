GUIA DE USO DE MICROSERVICIOS - SERVICIO ESCOLAR

1) ARQUITECTURA ACTUAL

- Frontend: http://localhost:8080
- Microservicio Alumnos: http://localhost:3001
- Microservicio Docentes: http://localhost:3002
- Microservicio Directivos: http://localhost:3003

Bases de datos separadas:
- Alumnos -> mongo-alumnos -> alumnos_db
- Docentes -> mongo-docentes -> docentes_db
- Directivos -> mongo-directivos -> directivos_db


2) LEVANTAR TODO EL SISTEMA

Desde la carpeta raiz del proyecto (donde esta docker-compose.yml):

docker compose up --build

En segundo plano:

docker compose up --build -d

Ver estado:

docker compose ps

Ver logs:

docker compose logs -f

Detener:

docker compose down


2.1) BOOTSTRAP INICIAL DE DIRECTIVO (SOLO PRIMERA VEZ)

Como las rutas de Directivos (excepto login) estan protegidas, primero debes crear un directivo semilla una sola vez.

En una terminal, dentro de servicio_directivo:

npm run seed:directivo

Comportamiento:
- Si no hay directivos, crea 1 directivo semilla.
- Si ya existe al menos 1 directivo, no crea otro.

Datos por defecto de la semilla:
- username: admin.directivo
- email: admin.directivo@escuela.edu.mx
- password: Admin1234

Despues de esto, usa login de directivo y continua con el flujo normal.


3) REGLAS DE AUTENTICACION IMPORTANTES

- En Directivos, solo el login es publico.
- GET /api/directivos, GET /api/directivos/:id y POST /api/directivos requieren token de directivo.
- Las rutas de Docentes estan protegidas por token de Directivo.
- Para usar rutas proxy de alumnos desde Docente, necesitas token de Docente.
- Las rutas protegidas de Alumnos aceptan token de Docente o Directivo (segun la ruta).
- Un Alumno tambien puede iniciar sesion y consultar solo su propia informacion.


3.1) NOTA DE BOOTSTRAP (PRIMERA EJECUCION)

Como POST /api/directivos ahora esta protegido, debes tener al menos 1 directivo semilla ya creado.

Opciones para primera vez:
- Opcion A (recomendada): insertar un directivo semilla directamente en Mongo con password hasheada.
- Opcion B (temporal): quitar middleware de auth en POST /api/directivos, crear 1 directivo, volver a proteger la ruta.

Una vez exista el directivo semilla, toda la administracion se hace por API con login.

5) RUTAS POR MICROSERVICIO

5.1) DIRECTIVOS (3003)

- POST /api/directivos/login (publica)
- GET /api/directivos (protegida)
- GET /api/directivos/:id (protegida)
- POST /api/directivos (protegida)

5.2) DOCENTES (3002) - protegidas por directivo

- POST /api/docentes
- POST /api/docentes/login
- GET /api/docentes
- GET /api/docentes/buscar?filtro=...
- PUT /api/docentes/:id
- DELETE /api/docentes/:id

5.3) ALUMNOS (3001)

Publicas:
- POST /api/alumnos
- POST /api/alumnos/login

Protegidas para docente/directivo:
- GET /api/alumnos/solo-info
- GET /api/alumnos/buscar?query=...
- PUT /api/alumnos/:id/carrera
- POST /api/alumnos/:id/materias
- GET /api/alumnos/:id/materias
- GET /api/alumnos/:id/materias/:materiaNombre/calificaciones
- PATCH /api/alumnos/:id/materias/:materiaNombre/unidades/:numUnidad

Protegidas para alumno autenticado:
- GET /api/alumnos/mi-info
- GET /api/alumnos/mis-materias
- GET /api/alumnos/mis-materias/:materiaNombre/calificaciones

Adicional:
- GET /api/alumnos/:id/mapa-curricular


6) PRUEBA RAPIDA MINIMA

1. Levantar docker compose.
2. Login directivo semilla y copiar TOKEN_DIRECTIVO.
3. Registrar docente con TOKEN_DIRECTIVO.
4. Login docente con TOKEN_DIRECTIVO y copiar TOKEN_DOCENTE.
5. Registrar alumno con TOKEN_DOCENTE.
6. Consultar alumnos con TOKEN_DOCENTE.


7) ERRORES COMUNES

- 401 Token no proporcionado: falta Authorization Bearer <token>.
- 403 Acceso denegado: token de rol incorrecto para esa ruta.
- 404 en proxy de alumnos: revisar que ALUMNOS_URL y rutas /api/alumnos esten correctas.
- ECONNREFUSED o ENOTFOUND: revisar que servicios Docker esten arriba y en la misma red.
